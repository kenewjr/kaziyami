# Architectural & Source Implementation Decisions

Format: `[Decision]: [Reason]. Alternative rejected: [Alternative].`

1. **Replace Kuronime and Otakudesu with NontonHentai**: Kuronime/Otakudesu are general-audience anime sites and fail the adult (NSFW) requirement; NontonHentai is verified adult hentai with Indonesian subs using identical AnimeStream engine. Alternative rejected: Keeping Kuronime with an adult disclaimer.
2. **Treat hanime.tv, hhanime.tv, and hanime1.me as distinct platforms**: `hhanime.tv` is a dead squatter domain (HTTP 302 redirect to parked ads); `hanime1.me` is a Chinese-language portal with Cloudflare Managed Challenge; `hanime.tv` is Astro SSR with direct HLS CDN. Alternative rejected: Aliasing all three domains under one extractor.
3. **Keep `eu.kanade.tachiyomi.animesource.*` and `eu.kanade.tachiyomi.animeextension.*`**: The Android extension classloader inside Aniyomi explicitly searches for this package structure and manifest meta-data. Alternative rejected: Renaming root packages to `app.kaziyami.*` which causes Aniyomi loader classnotfound crashes.
4. **Use `app.kaziyami.*` for internal utilities and multisrc modules**: Isolates proprietary networking, rate limiters, anti-bot guards, and extractors from upstream collisions. Alternative rejected: Keeping internal classes under `eu.kanade.tachiyomi.lib.core`.
5. **Lock permanent 64-bit Source IDs**: Derived from MD5 key hash `name/lang/1` matching Aniyomi upstream algorithm; changing them destroys users' bookmarks and watch history. Alternative rejected: Dynamic auto-generated IDs or integer IDs.
6. **Kototoro supported via dual-bridge**: Kototoro v2.3+ natively incorporates `source-host` with `AniyomiSourceRuntime` and `ApkExtensionConverter`, enabling direct Aniyomi extension APK execution, alongside a unified `kaziyami-kototoro-all-v1.4.1.jar` plugin. Alternative rejected: Maintaining a separate code repository for Kotatsu parser library.
7. **Use JDK standard `keytool` and `jarsigner` for release packaging**: Enables self-contained APK assembly and SHA-256 fingerprint extraction across Linux, macOS, and Windows without requiring multi-gigabyte Android SDK installations. Alternative rejected: Mandatory Android SDK / Gradle Android plugin dependency.
8. **Store relative URLs in `SAnime.url` and `SEpisode.url`**: Eliminates broken bookmarks when mirror domains change or fail over. Alternative rejected: Storing absolute URLs.
9. **Opt-in remote mirror list with strict HTTPS allowlist**: Static `mirrors.json` served over HTTPS from official repo `master` branch with regex domain allowlist; isolated client with zero cookies and zero custom headers. Alternative rejected: Automatic unvetted dynamic DNS lookup or remote code execution.
10. **Structured `SourceParseException` for selector drift**: Clear user-facing message while completely redacting query strings, tokens, and cookies from diagnostic details. Alternative rejected: Generic silent empty lists or unhandled IndexOutOfBoundsExceptions.
11. **Standalone Python source scaffolding tool (`scripts/new-source`)**: Automates creation of compliant source modules, Gradle configs, test skeletons, and enforces adult-only and evidence checklist. Alternative rejected: Manual copy-pasting of source boilerplate.
12. **Cross-platform preflight diagnostic tool (`scripts/preflight.py`)**: Diagnoses local user network, toolchain, DNS/ISP sinkhole blocking, Cloudflare barriers, and parser health without external dependencies; outputs sanitized report with zero cookies or tokens. Alternative rejected: Hardcoding DNS bypass or proxy logic into Android extensions.
13. **Local debug APK target (`assembleDebugAll`) and ADB installer (`scripts/install_debug.py`)**: Assembles debug-signed APKs to `build/kaziyami-debug` and installs directly via `adb install -r`, enabling zero-cost rapid local testing before signing and publishing. Alternative rejected: Requiring remote repository deployment before verifying basic playback on hardware.
14. **Pre-scrubbed diagnostic bundle generator (`scripts/collect_diagnostics.py`)**: Aggregates environment, preflight summary, extension versions, and scrubs cookies, bearer tokens, signed video URL query parameters, and IP addresses into a safe pasteable report. Alternative rejected: Expecting user to manually identify and redact sensitive tokens line-by-line.
15. **Token bucket with concurrency cap and jitter**: Prevent burst-triggered WAF blocks via local token bucket (3 req/s) and host-level concurrency semaphore (cap 1-2) with randomized micro-jitter. Alternative rejected: Unregulated parallel asynchronous fetches.
16. **Omit client hints when consistency cannot be proven**: Strict validation between `User-Agent` and `Sec-Ch-Ua*` hints via `BrowserProfile`; omit hints on any mismatch. Alternative rejected: Hardcoding desktop Windows Chrome client hints regardless of actual runtime UA.
17. **Sequential extractor resolution**: Prioritize user's preferred host and terminate extraction upon first working stream. Alternative rejected: Hammering every candidate embed host in parallel.
18. **Host-level circuit breaker with fail-fast**: Pause requests after 4 consecutive failures for 30s cooldown. Alternative rejected: Retrying endlessly against offline or hard-blocked origins.
19. **Publish artifacts exclusively on orphan `repo` branch**: Keep build output (`repo/apk/`, `repo/index.json`, `repo/index.min.json`, `repo/sha256sums.txt`) out of `master` via `.gitignore`. Alternative rejected: Tracking compiled binaries and generated index files directly on the master development branch.
20. **Host runtime dependency pin in `docs/STACK.md`**: Enforce host-provided library versions (Kotlin 1.9, OkHttp 4.12, kotlinx-serialization 1.6); block major jumps (Kotlin 2+, OkHttp 5+, JUnit 6+) to prevent classloader collisions. Alternative rejected: Merging unvetted automated Dependabot major version bumps.
21. **Kototoro GPL isolation**: Keep core engine and adapters under MIT; interact with Kototoro's Apache-2.0 `source-host` reflection ABI rather than linking against GPLv3 `kototoro-parsers`. Alternative rejected: Re-licensing the repo or linking GPL copyleft dependencies.

Standalone JARs provide zero anti-bot, performance, or challenge-handling advantages over APKs, and duplicate build pipelines. Alternative rejected: Building and maintaining a separate non-standard JAR plugin distribution.

Alternative rejected: Inventing undocumented manifest headers, fictional UI menu paths, or TVBox/CloudStream packaging.
