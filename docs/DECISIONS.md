# Architectural & Source Implementation Decisions

Format: `[Decision]: [Reason]. Alternative rejected: [Alternative].`

1. **Replace Kuronime and Otakudesu with NontonHentai**: Kuronime/Otakudesu are general-audience anime sites and fail the adult (NSFW) requirement; NontonHentai is verified adult hentai with Indonesian subs using identical AnimeStream engine. Alternative rejected: Keeping Kuronime with an adult disclaimer.
2. **Treat hanime.tv, hhanime.tv, and hanime1.me as distinct platforms**: `hhanime.tv` is a dead squatter domain (HTTP 302 redirect to parked ads); `hanime1.me` is a Chinese-language portal with Cloudflare Managed Challenge; `hanime.tv` is Astro SSR with direct HLS CDN. Alternative rejected: Aliasing all three domains under one extractor.
3. **Keep `eu.kanade.tachiyomi.animesource.*` and `eu.kanade.tachiyomi.animeextension.*`**: The Android extension classloader inside Aniyomi explicitly searches for this package structure and manifest meta-data. Alternative rejected: Renaming root packages to `app.kaziyami.*` which causes Aniyomi loader classnotfound crashes.
4. **Use `app.kaziyami.*` for internal utilities and multisrc modules**: Isolates proprietary networking, rate limiters, anti-bot guards, and extractors from upstream collisions. Alternative rejected: Keeping internal classes under `eu.kanade.tachiyomi.lib.core`.
5. **Lock permanent 64-bit Source IDs**: Derived from MD5 key hash `name/lang/1` matching Aniyomi upstream algorithm; changing them destroys users' bookmarks and watch history. Alternative rejected: Dynamic auto-generated IDs or integer IDs.
6. **Kototoro supported via dual-bridge**: Kototoro v2.3+ natively incorporates `source-host` with `AniyomiSourceRuntime` and `ApkExtensionConverter`, enabling direct Aniyomi extension APK execution, alongside a unified `kaziyami-kototoro-all-v1.4.1.jar` plugin. Alternative rejected: Maintaining a separate code repository for Kotatsu parser library.
7. **Use JDK standard `keytool` and `jarsigner` for release packaging**: Enables self-contained APK assembly and SHA-256 fingerprint extraction across Linux, macOS, and Windows without requiring multi-gigabyte Android SDK installations. Alternative rejected: Mandatory Android SDK / Gradle Android plugin dependency.
8. **Store relative URLs in `SAnime.url` and `SEpisode.url`**: Eliminates broken bookmarks when mirror domains change or fail over. Alternative rejected: Storing absolute URLs.
9. **Opt-in remote mirror list with strict HTTPS allowlist**: Static `mirrors.json` served over HTTPS from official repo `master` branch with regex domain allowlist; isolated client with zero cookies and zero custom headers. Alternative rejected: Automatic unvetted dynamic DNS lookup or remote code execution.
10. **Structured `SourceParseException` for selector drift**: Clear user-facing message while completely redacting query strings, tokens, and cookies from diagnostic details. Alternative rejected: Generic silent empty lists or unhandled IndexOutOfBoundsExceptions.
11. **Standalone Python source scaffolding tool (`scripts/new-source`)**: Automates creation of compliant source modules, Gradle configs, test skeletons, and enforces adult-only and evidence checklist. Alternative rejected: Manual copy-pasting of source boilerplate.
12. **Cross-platform preflight diagnostic tool (`scripts/preflight.py`)**: Diagnoses local user network, toolchain, DNS/ISP sinkhole blocking, Cloudflare barriers, and parser health without external dependencies; outputs sanitized report with zero cookies or tokens. Alternative rejected: Hardcoding DNS bypass or proxy logic into Android extensions.
13. **Local debug APK target (`assembleDebugAll`) and ADB installer (`scripts/install_debug.py`)**: Assembles debug-signed APKs to `build/kaziyami-debug` and installs directly via `adb install -r`, enabling zero-cost rapid local testing before signing and publishing. Alternative rejected: Requiring remote repository deployment before verifying basic playback on hardware.
14. **Pre-scrubbed diagnostic bundle generator (`scripts/collect_diagnostics.py`)**: Aggregates environment, preflight summary, extension versions, and scrubs cookies, bearer tokens, signed video URL query parameters, and IP addresses into a safe pasteable report. Alternative rejected: Expecting user to manually identify and redact sensitive tokens line-by-line.
15. **Token bucket with concurrency cap and jitter**: Prevent burst-triggered WAF blocks via local token bucket (3 req/s) and host-level concurrency semaphore (cap 1-2) with randomized micro-jitter. Alternative rejected: Unregulated parallel asynchronous fetches.
16. **Omit client hints when consistency cannot be proven**: Strict validation between `User-Agent` and `Sec-Ch-Ua*` hints via `BrowserProfile`; omit hints on any mismatch. Alternative rejected: Hardcoding desktop Windows Chrome client hints regardless of actual runtime UA.
17. **Sequential extractor resolution**: Prioritize user's preferred host and terminate extraction upon first working stream. Alternative rejected: Hammering every candidate embed host in parallel.
18. **Host-level circuit breaker with fail-fast**: Pause requests after 4 consecutive failures for 30s cooldown. Alternative rejected: Retrying endlessly against offline or hard-blocked origins.
19. **Publish artifacts exclusively on orphan `repo` branch**: Keep build output (`repo/apk/`, `repo/index.json`, `repo/index.min.json`, `repo/sha256sums.txt`) out of `master` via `.gitignore`. Alternative rejected: Tracking compiled binaries and generated index files directly on the master development branch.
20. **Host runtime dependency pin in `docs/STACK.md`**: Enforce host-provided library versions (Kotlin 1.9, OkHttp 4.12, kotlinx-serialization 1.6); block major jumps (Kotlin 2+, OkHttp 5+, JUnit 6+) to prevent classloader collisions. Alternative rejected: Merging unvetted automated Dependabot major version bumps.
21. **Kototoro GPL isolation**: Keep core engine and adapters under MIT; interact with Kototoro's Apache-2.0 `source-host` reflection ABI rather than linking against GPLv3 `kototoro-parsers`. Alternative rejected: Re-licensing the repo or linking GPL copyleft dependencies.
22. **Maintain `hanime.tv` as primary base**: `hhanime.tv` is confirmed a defunct parked squatter redirecting to ads; `hanime.tv` is verified production Astro SSR. Alternative rejected: Pointing users to a parked ad domain.
23. **Do not distribute standalone JAR by default for Kototoro**: Kototoro Android natively loads standard Aniyomi extension APKs via `ChildFirstPathClassLoader` (`AniyomiExtensionLoader.kt`), and Kototoro Desktop/iOS converts APKs dynamically via `ApkExtensionConverter.kt`. Standalone JARs provide zero anti-bot, performance, or challenge-handling advantages over APKs, and duplicate build pipelines. Alternative rejected: Building and maintaining a separate non-standard JAR plugin distribution.
24. **Pin `ubuntu-24.04` and upgrade core GitHub Actions to Node 24 runtime**: Pinned OS runner across all workflows (`ci.yml`, `publish.yml`, `smoke.yml`, `monitor.yml`) to `ubuntu-24.04` to ensure deterministic execution. Updated actions to major versions running on Node 24: `actions/checkout@v5` (v5.1.0, SHA `fbc6f3992d24b796d5a048ff273f7fcc4a7b6c09`), `actions/setup-java@v5` (v5.7.0, SHA `b6effb05e454b25005698d916606bdc6ffcbf961`), `actions/setup-python@v7` (v7.1.0, SHA `6d4fd22b20465ccc0f7354476588e8df7c9ca0e0`), `gradle/actions/setup-gradle@v5` (v5.0.2, SHA `0723195856401067f7a2779048b490ace7a47d7c`), and `actions/upload-artifact@v7` (v7.0.2, SHA `cf430e030ddbb5b0abf93d22962f4752f3646cd9`). Configured `gradle/actions/setup-gradle` with `cache-overwrite-existing: true` and non-fatal fallback to insulate CI against transient cache service errors. Alternative rejected: Retaining deprecated Node 20 runtimes and floating `ubuntu-latest`.
25. **Unified Dual Distribution Architecture (Phase 10)**: Ship both Variant A (Aniyomi APK extension repo) and Variant B (Kototoro JAR plugin repo) generated from the same core engine (`KaziyamiSource`). Bundles Dalvik executable `classes.dex` for Android ART and Java `.class` files for Desktop JVM in dual-runtime FAT JARs. Alternative rejected: Single APK-only or maintaining separate disparate codebases.
26. **Monotonic `versionCode` and Strict Integer Update Rules (Phase 11)**: Kototoro update policy requires strictly `remote.versionCode > installed.versionCode` (`ExtensionUpdatePolicy.kt:5-7`). Both APK and JAR repository indexes emit monotonic integer build codes. Downgrades and same-version republishing are rejected. Alternative rejected: Semver string comparison or floating version tags.
27. **Atomic Rollback & Version Retention (Phase 11)**: Keep the previous 3 versions of every APK and JAR file on the `repo` branch to allow immediate user and automated rollback. If `verifyPublishedRepo` fails over HTTPS, the workflow automatically rolls back repository index files to the last known good commit. Alternative rejected: Overwriting releases in-place or pruning previous versions immediately.
28. **Self-Contained Kototoro JAR Packaging and Strict Host Class Exclusion (CI Fix)**: `KototoroPackagingTest` root cause was twofold: (a) looking for obsolete artifact name `kaziyami-kototoro-all-v1.4.1.jar` instead of dynamic `kaziyami-all-v1.4.2.jar`, and (b) `:core:test` lacked a Gradle task dependency on `packageKototoroPlugin`, causing tests on clean workspaces to fail when classes were not pre-compiled. Additionally, packaging was bundling host `parser-api` interfaces into the plugin JAR, violating the Kototoro ClassLoader isolation boundary. Resolved by wiring `:core:test` to `packageKototoroPlugin`, excluding all host classes from the JAR, unifying JVM toolchain to JDK 17, and validating bytecode versions (55..61) in contract tests. Alternative rejected: Mocking the packaging script or softening test assertions.
29. **Ground-Truth Kototoro JAR Plugin and Repo Specification (Phase 10 Revised)**: Kototoro parser plugins do not use `META-INF/services/` or `AndroidManifest.xml` for discovery. Kototoro's `JarExtensionLoader` reflects `org.skepsun.kototoro.parsers.ContentParserFactoryKt.newParser(ContentParserSource, ContentLoaderContext): ContentParser` and enumerates sources from `ContentParserSource` enum constants. Android ART host requires `classes.dex`, while Desktop JVM host requires standard `.class` files. Repository index is a direct JSON array of `ExtensionIndexDto` (`[{"name":...,"pkg":...,"apk":...,"lang":...,"code":...,"version":...,"nsfw":...}]`) located under `<repo>/apk/<apk_file>`. UI navigation paths verified directly against Kototoro source (`Explore` -> `Manage` -> `Repositories` / `Packages`). Verified via `samples/kototoro-hello`, `verifyJars`, and isolated reflection contract tests. Alternative rejected: Inventing undocumented manifest headers, fictional UI menu paths, or TVBox/CloudStream packaging.
30. **Omit `index_v2` in `repo.json` for Kototoro Compatibility**: In Kototoro's `ExtensionRepoService.kt:203-208`, the presence of `index_v2` triggers a recursive `fetchRepoDetails` call. Because `index.min.json` is not `index.pb`, Kototoro attempts to fetch `index.min.json/repo.json`, causing an HTTP 404 error and failing repository registration. Omitting `index_v2` allows Kototoro to immediately register the repository metadata and load `index.min.json`. Alternative rejected: Simulating fake protobuf routes.
31. **Modern Android Privacy & Target SDK 34 Baseline**: Upgraded `targetSdkVersion` from `33` to `34` (Android 14) and added explicit `android.permission.INTERNET` declaration in extension manifests. Modern Android 14 and 15 Play Protect block or warn on apps targeting deprecated SDKs (`< 24` blocked, `< 34` triggers 'Unsafe app blocked' warning). Retained `minSdkVersion=21` for full backward compatibility across Android 7–15. Concurrently upgraded icon pipeline in `tools/generate_icons.py` to generate distinct procedural vector logo emblems for all six sources and published `"icon"` metadata in both Aniyomi and Kototoro repository indexes. Alternative rejected: Retaining `targetSdkVersion=33` and generic single-letter placeholder icons.
32. **Unified Single-Suite Kototoro Repository Index & `GET$default` ABI Fix**: Kototoro's `source-host` provides `eu.kanade.tachiyomi.animesource.online.AnimeHttpSource` on the host root ClassLoader (`classes3.dex`). Calling methods with default arguments (`GET(url, headers = ...)`) compiled into static synthetic calls `AnimeHttpSource.GET$default(...)`, which Kototoro's host class does not possess, throwing runtime `NoSuchMethodError`. Replaced default parameters in `AnimeHttpSource` with explicit Java/Kotlin overloads (`GET(url)` and `GET(url, headers)`), emitting direct virtual invocations (`invokevirtual`). In addition, unified `repo/jar/index.min.json` to index only the all-in-one suite (`app.kaziyami.kototoro` / `kaziyami-all-v<ver>.jar`) containing all 6 sources, matching official Kototoro parser repositories (`k-parsers-r`) and eliminating package fragmentation and duplicate registrations. Alternative rejected: Requiring users to manage 7 separate JAR packages or forcing upstream Kototoro to patch host classes.
33. **Authentic Website Icons & High-Resolution Asset Pipeline**: Replaced procedural synthetic icons with authentic official site icons and logos directly sourced from the live platforms:
- Nekopoi: Official cat emblem cropped from `nekopoi.care` logo.
- IndoHentai: Official site favicon from `indohentai.net`.
- NontonHentai: Official 300x300 site icon from `nontonhentai.net`.
- Hentaimama: Official site heart/crown mark from `hentaimama.io`.
- JAVSubbed: Official 100x100 site icon from `javsubbed.net`.
- Hanime: Official Apple touch icon from `hanime.tv`.
Archived raw assets under `art/raw_icons/` ensuring 100% offline build determinism and CI stability. `tools/generate_icons.py` syncs authentic 192x192 icons to `art/icons/`, `repo/icon/`, `repo/jar/`, and Android APK launcher drawables. Alternative rejected: Scraping live websites dynamically during Gradle builds or using generic synthetic placeholders.
34. **Baseline v0.0.1 Extension & Suite Versioning**: Configured `libVersion = "0.0"` and `extVersionCode = 1` across all 6 sources, establishing both APK (Variant A) and JAR (Variant B) distributions at initial production baseline `0.0.1` (`versionCode = 1`). Preserved all permanent 64-bit source IDs and host compatibility invariants. Alternative rejected: Retaining development `1.4.x` version numbers.
35. **Exclusively Repository Branch Distribution & Single Unified JAR**: Following Aniyomi (`aniyomiorg/aniyomi-extensions`) and Kototoro (`skepsun/k-parsers-r`) standards, extension binaries are distributed exclusively via HTTP repository metadata on the `repo` branch (`repo/index.min.json` for Aniyomi APKs and `repo/jar/index.min.json` for Kototoro JARs). Removed GitHub Releases asset publishing to eliminate pipeline overhead and clutter. For Kototoro (Variant B), all 6 sources are packaged into one single unified JAR (`kaziyami-all-v*.jar`), enabling users to install a single package and selectively enable/disable individual sources via Kototoro's native UI. Alternative rejected: Uploading duplicate binary assets to GitHub Releases and producing individual single-source JARs.
36. **Baseline 1.0.0 & SmartDns Loopback / ISP Sinkhole Decoupling**: Reset unified extension baseline to `1.0.0` (`extVersionCode = 1`, `libVersion = "1.0"`). Integrated `SmartDns` in `NetworkHelper` for automatic DNS-over-HTTPS fallback (Cloudflare `1.1.1.1` & Google `8.8.8.8`) on Indonesian ISP sinkhole blocking (`36.86.63.*`, `180.250.*`, `118.98.*`, `10.10.*`). Decoupled loopback (`127.0.0.1`, `localhost`, `isLoopbackAddress`) from sinkhole sets to eliminate MockWebServer / local DNS interception delays in CI/dev environments. Alternative rejected: Retaining `127.0.0.1` inside sinkhole list which triggered false DoH lookups for local endpoints.
37. **Pin `libVersion = "14"` for Aniyomi Framework ABI & Embed JAR Manifest Icons**: Kototoro's `AniyomiExtensionLoader` requires `tachiyomi.animeextension.version` / `tachiyomix.extensionLib` to be within range `12..16` (integer `14` / `1.4`), crashing with `outside kototoro supported range` when set to `"1.0"`. Pinned `libVersion = "14"` in all `build.gradle.kts` files while maintaining user release `extVersion = "1.0.0"` (`extVersionCode = 2`). Additionally embedded `app.kaziyami.kototoro.png`, `res/drawable/ic_launcher.png`, and `android:icon="@drawable/ic_launcher"` into `kaziyami-all-v1.0.0.jar` to resolve blank white icons in Kototoro package browser. Alternative rejected: Conflating framework ABI version with extension release version or omitting launcher drawables from JAR packages.
38. **Decouple `GenericThemeSource` from host Injekt and format APK `versionName` as `14.2`**: Kototoro's `SourceTester` marked JAR sources as unavailable because `AnimeHttpSource` on Kototoro's host root ClassLoader accesses `network by injectLazy()`, which throws `Injekt` uninitialized exceptions inside `JarExtensionLoader`. Decoupled by overriding `client` and `headersBuilder()` in `GenericThemeSource` and adding `open fun headersBuilder()` in `core/AnimeHttpSource.kt`. Concurrently aligned APK `versionName` to `14.2` (`libVersion.extVersionCode`) and added `<meta-data android:name="aniyomix.extensionLib" android:value="{meta['libVersion']}" />` to APK manifests, satisfying both official Aniyomi (`aniyomix.extensionLib`) and Kototoro (`versionName.substringBefore('.').toDoubleOrNull() >= 12.0`) ABI range requirements without breaking the unified `1.0.0` Kototoro JAR suite. Alternative rejected: Retaining `versionName="1.0.0"` in APKs which Kototoro parses as `1.0 < 12.0`, causing "outside supported range" errors.
39. **Compile against real extensions-lib-14 as compileOnly and isolate test doubles to test source sets**: Vendoring private stubs of `AnimeHttpSource` in `core/src/main` caused Kotlin to emit `invokevirtual GenericThemeSource.GET(String)` rather than calling top-level `eu.kanade.tachiyomi.network.GET$default`, triggering runtime `NoSuchMethodError` on device, while packaging 55 host classes into APKs. Compiling against official `extensions-lib:14` as `compileOnly` and isolating working test doubles strictly to `core/src/test` ensures strict host ABI compatibility, prevents host class bundling, and allows 100% offline unit tests to pass without `Stub!` exceptions. Alternative rejected: Maintaining private stubs in production source sets or mocking extension APIs in tests.
40. **Discontinue Kototoro JAR format for video and designate Variant A (Aniyomi APK) as sole video route**: Kototoro's `parser-api` `ContentParser` interface models only manga image pages and novel text (`getPages`, `getChapterContent`). Kototoro's video playback routes exclusively through `AniyomiExtensionLoader` APKs; attempting to load video parsers via JAR triggers 'manga is not supported' or 'This video source is not supported'. Discontinuing JAR artifacts eliminates fragmentation and focuses on the single verified, native video loader in Kototoro. Alternative rejected: Attempting to shoehorn video streaming into Kototoro's manga/novel parser interface.
